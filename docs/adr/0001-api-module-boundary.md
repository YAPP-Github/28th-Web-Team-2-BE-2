# ADR-0001: `api` 실행 모듈과 루트 집계 프로젝트의 경계

- 상태: Accepted
- 결정일: 2026-08-08

## 배경

기존 루트 프로젝트가 Spring Boot 실행 설정, 애플리케이션 소스, 테스트, JaCoCo를 모두 소유하고 있어 새 모듈을 추가할 때 실행 책임과 공통 Gradle 설정의 경계가 섞였다.

## 결정

- 실행 가능한 Spring Boot 애플리케이션과 테스트는 `api` 모듈이 소유한다.
- 루트 프로젝트는 Gradle 집계, 공통 group/version, 의존성 관리와 공통 플러그인 설정만 소유한다.
- `common`은 공통 계약과 예외를, `external:kamis-client`는 KAMIS 외부 계약과 클라이언트를 소유한다.
- API 모듈이 사용하는 외부 라이브러리는 전이 의존성에 기대지 않고 `api/build.gradle`에 직접 선언한다.

## 대안과 trade-off

- 루트에 실행 애플리케이션을 유지하면 당장 파일 이동은 없지만, 모듈별 실행·검증 경계를 만들기 어렵다.
- `core` 모듈을 추가하면 도메인과 애플리케이션을 더 분리할 수 있지만, 현재 요구사항에는 구현 책임과 의존성 경계만 늘어난다.
- `api`를 실행 모듈로 두면 구조가 단순하고 현재 API 흐름을 보존하면서 외부·공통 모듈을 점진적으로 분리할 수 있다.

## 영향

- 루트에서는 `bootRun`, `bootJar`, API 테스트를 직접 실행하지 않고 `:api` 작업을 실행한다.
- 소스·테스트·JaCoCo 보고서 경로는 `api` 아래에 있다.
- 향후 별도 `core` 모듈이 필요해지는 조건은 API가 아닌 실행 환경에서도 도메인·애플리케이션 로직을 재사용해야 하거나, API와 독립된 계약 검증이 필요해지는 경우다.
